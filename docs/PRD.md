# MyGateway 产品需求文档（PRD）

面向个人开发者和小团队的轻量 AI API 网关。本文档为产品特性与行为的权威来源；
技术实现见 [架构](ARCHITECTURE.md) 与 [详细设计](DESIGN.md)。

## 1. 产品概述

- **定位**：部署在用户自有 Cloudflare 账号中的 AI API 网关，统一管理多个模型供应商。
- **对外形态**：OpenAI Chat / Responses、Anthropic Messages 兼容端点 + 管理控制台。
- **核心承诺**：一个 Gateway Key 接入全部模型；固定、可解释的路由顺序；响应前 Fallback；
  自带限流、预算、费用统计与请求日志。
- **约束**：适配 Cloudflare Free Tier，不引入 KV、R2、Queues、Durable Objects 等额外组件。

典型使用流程：

```text
部署并修改初始密码
  → 添加供应商渠道（检测连接与模型）
  → 创建统一模型并绑定渠道模型
  → 创建 Gateway Key
  → 调用 /v1/chat/completions、/v1/responses 或 /v1/messages
```

### 产品原则

1. **好用易用**：一个 Key 即可接入，控制台一站式管理；默认配置即开即用。
2. **固定路由**：默认按保存后的固定优先级路由，不做随机、轮询或动态成本调度。
3. **原生优先**：客户端协议优先转发到供应商同协议端点。
4. **有限转换**：只转换明确支持的 Chat / Messages 公共子集，不能无损表达时直接报错。
5. **响应前回退**：一旦向客户端提交响应字节，不再跨渠道续接。
6. **默认不存内容**：不保存 Prompt/Response；显式开启"记录上下文"后仅加密保存 4 KiB 预览并短期保留。
7. **统计不冒充账单**：Token 和余额以 Provider 返回值为准，未知用量单独标记。
8. **需求先确认**：新需求先讨论目标、范围和取舍；确认后先更新本文档，再开始设计与实施。

### 版本结论

当前为 **0.1.x 原型 / public alpha**：核心调用闭环已经完成，适合个人自用和小团队试用；
多币种费用准确性、真实 SDK 回归、Free Tier 生产基线和管理登录防暴力破解尚未达到稳定版标准。

状态定义：✅ 已实现并有自动化覆盖；🚧 已有可用子集或存在已知准确性边界；⬜ 尚未实现。

## 3. 已实现特性详述

### 3.1 管理控制台

- **认证**：D1 单管理员账号、HttpOnly Session；首次登录强制修改用户名和密码。
- **i18n**：中英双语，顶部语言开关，选择持久化（localStorage）。
- **外观**：左右布局、可收缩侧边栏、浅色/暗黑主题、响应式；图表支持 `prefers-reduced-motion`。
- **模块**：概览（Dashboard）、渠道、模型、API Keys、Analytics（用量分析 / 请求日志）、System。
- **快速调用**：首页可创建 1 小时有效的临时 Gateway Key，并把已生成的调用命令复制到剪贴板。
  明文只缓存在当前站点的浏览器 `localStorage`，刷新页面后在到期前仍可继续复制；到期时自动
  清除并恢复为未创建状态，不通过管理 API 再次读取明文。

### 3.2 渠道

- **预制渠道**：预置渠道只要求输入 Key，服务端按已确认的供应商元数据写入 Chat、Responses、
  Messages 等原生协议；模型列表不得用于推测协议能力。预置渠道编辑页只读展示协议与端点，
  只允许修改名称和 Key；自定义渠道才允许编辑协议地址。
- **检测与导入**：添加渠道必须先执行"检测连接与模型"，并在提交前展示协议、检测结果和模型
  清单；检测阶段不创建渠道、不写 D1，连接信息或 Key 改动后必须重新检测。检测完成后展示可
  勾选模型清单，默认全选，支持全选/取消全选/逐项选择；"保存"只保存渠道及完整模型库存，
  "保存并导入网关"只导入已勾选模型。检测失败视为已完成一次预检，允许仅保存后手工维护；
  未勾选模型时禁用导入。
- **卡片交互**：渠道页为响应式竖向卡片网格，以现有卡片的精简样式（头部、指标占位、内容骨架
  与底部添加按钮）作为添加入口，不提供渠道搜索；现有卡片展示状态、协议、缓存余额、套餐余量占位、
  模型总数和最多 3 个模型预览（其余以 `+N` 表示）。高频操作"编辑"和"测试"直接可见，
  启停、删除等低频操作收纳到更多菜单。保存成功展示轻量完成动效与持续成功状态，不阻塞
  余额查询、模型导入或后续操作。
- **摘要性能**：多渠道摘要使用批量查询，不按卡片产生 N+1 查询；模型发现与余额查询只由
  用户操作触发，不使用 Cron。
- **删除**：删除渠道前展示关联实例与受影响统一模型数量；有其他渠道实例的模型只移除当前
  实例，失去最后实例的模型在确认后软删除（历史 usage 保留）。

### 3.3 模型

- **创建**：从模型网格内与真实模型卡片同构的精简新增卡片进入创建表单；支持从渠道库存勾选
  导入，或从 30 个常见模板 / 自由输入创建。
- **结构**：统一模型（unified model）+ 渠道实例（channel instance），可编辑 ID 与稳定直达
  别名；同一模型可绑定多个渠道实例，按实例顺序路由。
- **定价**：每个渠道实例可配置输入 / 输出 / 缓存命中单价（每百万 Token）和 USD / CNY
  币种元数据。

### 3.4 价格库（model_prices）

- 管理员可维护模型基准价（输入 / 输出 / 缓存，USD/CNY），渠道导入时自动预填表单。
- 内置 30 个经官方页面核验的主流模型 USD 按量基线；分层计价模型采用最短上下文首档，完整
  口径、核验日期与来源见[供应商与模型](PROVIDERS.md)。升级只替换仍等于旧内置值的行，不覆盖
  管理员已经修改的价格。
- **优先级**：渠道实例价 > 价格库基准价 > 未定价（不计费）。
- 请求完成时按 Provider 上报 Token 和实例价格计算整数 micros，缓存 Token 使用缓存价；结果
  汇总到用量、密钥每日用量与首页指标。
- **已知限制**：当前聚合表只有 `cost_micros`，没有币种维度，也没有汇率换算。因此不同币种
  混用时汇总值不具备财务意义。修复前部署者应统一使用一种记账币种，界面中的费用只能视为估算。

### 3.5 密钥与限额

- **生命周期**：创建、一次性明文展示、启停和删除。创建与编辑时可选择精确到本地日期和时间
  的到期时间，留空表示永不过期；列表显示具体到期时刻和“已过期”状态，并允许直接续期。
  后端仍保留重新生成兼容接口，但当前控制台不提供入口。
- **限额**：每分钟 RPM（isolate 内尽力窗口）、每日请求 / Token 预算（D1 权威扣减）、到期
  时间、模型白名单；超额返回 429/403，密钥过期返回 401。

### 3.6 网关协议与路由

- **协议**：OpenAI Chat、OpenAI Responses、Anthropic Messages。
- **转换**：Chat ↔ Messages 的文本、工具调用、usage 和 SSE 公共子集；无法无损表达时直接报错。
- **路由**：原生协议优先、固定优先级、完整别名直达。
- **Fallback**：连接错误、超时、408、429、部分 5xx 和可靠额度不足错误；只在响应开始前回退。
- **熔断**：连续故障后在当前 isolate 冷却，不主动探测 Provider。
- **流式**：SSE 增量解析与透传，客户端取消向上游传播。

### 3.7 用量与 Analytics

- **聚合**：5 分钟聚合桶（始终记录，不受日志开关影响），维度为密钥 / 统一模型 / 最终渠道，
  分别记录总输入、缓存命中与输出 Token，并额外记录流式 TTFT、延迟采样数和回退信息；保留期
  与 usage 一致（30 天）。
- **用量分析页**：今日 / 7 天 / 30 天与日历点选的自定义时间范围、模型和密钥过滤、聚合粒度（5 分钟 /
  小时 / 天）；指标卡（请求量、平均延迟、平均首 Token 延迟、成功率、Token、预估费用）；首
  Token 延迟仅统计能够观察到首个有效输出的流式请求，无流式样本时显示 `—`；
  Request trend 折线图与 Token consumption 三色堆叠柱状图（非缓存输入 / 缓存 / 输出，含真实
  时间轴、数值轴、单位和时间标签）；两张图桌面端 1:1 并排、移动端堆叠；图表
  根据可视宽度将原始桶合并为最多 48 个展示桶，使分钟、小时、天粒度具有一致的线宽与柱宽；
  7 天范围默认按天聚合，前端以零值补齐无请求桶；模型维度明细表。
- **分析导航与筛选**：用量和日志页在标题下展示用途副标题，共用轻量胶囊分段导航；筛选控件
  采用 48px 等高、弱边框和大圆角，桌面端按主要维度排成一行，窄屏自动切换为两列或单列。
- **写入**：完成路径一次 D1 `batch()` 提交聚合、密钥日用量与可选日志，同一 `waitUntil`
  执行，不阻塞模型响应。

### 3.8 请求日志与可观测

- **开关**：总开关 + 异常 / 正常日志独立开关；关闭时完全不写 `request_logs`。
- **上下文**：默认关闭；开启需二次确认，请求和响应各最多 4 KiB 预览，`MASTER_KEY` 派生密钥
  AES-GCM 加密存储，列表接口绝不返回上下文明文。
- **筛选与分页**：状态、模型、密钥、渠道、精确 Request ID；游标分页，默认不轮询、不
  COUNT，最多 100 条/页；详情抽屉展示路由尝试、回退、Token、费用、延迟、脱敏错误。
- **保留**：日志 1–7 天（控制台可调），每日 Cron 清理。
- **可观测**：脱敏结构化日志、`X-Gateway-Timing`、`Server-Timing`、`/health`、
  `/v1/openapi.json` + `/v1/api-docs`。

### 3.9 安全

- Provider Key 用 `MASTER_KEY` AES-GCM 加密存储；Gateway Key 服务端只存哈希，普通密钥明文
  只显示一次。首页 1 小时临时密钥按 3.1 节约定在当前浏览器保留至到期。
- 控制台需要登录；日志不记录任何密钥凭证；默认不存对话内容。

## 4. 产品边界（当前明确不做）

- Responses 与 Chat / Messages 之间的协议转换；
- Gemini 原生协议、Embeddings、Images、Audio、Realtime、Batch 和 Files；
- 同渠道自动重试、流输出后的 Fallback；
- 动态价格路由、自动套餐扣减和精确账单；
- OAuth Provider、多用户、RBAC、Team/Project；
- Prompt/Response 存储或语义缓存；
- 跨 isolate 强一致的熔断、限流或预算状态（RPM 为 per-isolate 尽力窗口，每日预算以 D1 为准）。

## 5. Roadmap

### P0：稳定版前必须完成

- 为 Analytics、请求日志和密钥日用量补齐币种维度，或明确收敛为单一记账币种；迁移后 UI
  必须分币种展示，禁止把 CNY 与 USD 相加后标成美元；
- 增加管理登录失败的有界限速，并补充认证 API 安全测试；
- 使用 OpenAI SDK 验证 Chat 与原生 Responses 的真实流式 / 非流式调用；
- 使用 Anthropic SDK 验证原生 Messages 与 Messages → Chat 转换；
- 建立 Free Tier 生产指标基线（CPU、D1 rows read/write、缓存命中率）。

### P1：近期体验

- 完善自定义渠道协议端点编辑校验和变更影响提示；
- 完善 Anthropic 错误 envelope 和图片内容公共子集；
- 密钥页面展示每日用量与剩余预算。

### P2：后续候选

- Provider Adapter 能力矩阵与更多官方余额接口；
- Responses ↔ Chat 转换；
- 缓存命中的预算扣减策略；
- 多用户和 RBAC；
- 只有需要共享强状态时再评估 Durable Objects。

Roadmap 不是已承诺的发布日期；已发布变化以 [CHANGELOG](../CHANGELOG.md) 为准。
