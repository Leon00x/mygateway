# MyGateway 产品需求文档（PRD）

面向个人开发者和小团队的轻量 AI API 网关。本文档为产品特性与行为的权威来源；
技术实现见 [架构](ARCHITECTURE.md) 与 [详细设计](DESIGN.md)。

## 1. 产品概述

- **定位**：部署在用户自有 Cloudflare 账号中的 AI API 网关，统一管理多个模型供应商。
- **对外形态**：OpenAI Chat / Responses、Anthropic Messages 兼容端点 + 管理控制台。
- **核心承诺**：一个 Gateway Key 接入全部模型；固定、可解释的路由顺序；响应前 Fallback；
  自带限流、预算、费用统计与请求日志。
- **约束**：适配 Cloudflare Free Tier，不引入 KV、R2、Queues、Durable Objects 等额外组件。

典型使用流程：

```text
部署并修改初始密码
  → 添加供应商渠道（检测连接与模型）
  → 创建统一模型并绑定渠道模型
  → 创建 Gateway Key
  → 调用 /v1/chat/completions、/v1/responses 或 /v1/messages
  →（可选）创建 Management Key 并安装官方 Skills，由 AI Agent 管理网关
```

### 产品原则

1. **好用易用**：一个 Key 即可接入，控制台一站式管理；默认配置即开即用。
2. **固定路由**：默认按保存后的固定优先级路由，不做随机、轮询或动态成本调度。
3. **原生优先**：客户端协议优先转发到供应商同协议端点。
4. **有限转换**：只转换明确支持的 Chat / Messages 公共子集，不能无损表达时直接报错。
5. **响应前回退**：一旦向客户端提交响应字节，不再跨渠道续接。
6. **默认不存内容**：不保存 Prompt/Response；显式开启"记录上下文"后仅加密保存 4 KiB 预览并短期保留。
7. **统计不冒充账单**：Token 和余额以 Provider 返回值为准，未知用量单独标记。
8. **需求先确认**：新需求先讨论目标、范围和取舍；确认后先更新本文档，再开始设计与实施。

### 版本结论

当前为 **0.1.x 原型 / public alpha**：核心调用闭环已经完成，适合个人自用和小团队试用；
多币种费用准确性、真实 SDK 回归、Free Tier 生产基线和管理登录防暴力破解尚未达到稳定版标准。

状态定义：✅ 已实现并有自动化覆盖；🚧 已有可用子集或存在已知准确性边界；⬜ 尚未实现。

## 3. 已实现特性详述

### 3.1 管理控制台

- **认证**：D1 单管理员账号、HttpOnly Session；首次登录强制修改用户名和密码。
- **i18n**：中英双语，顶部语言开关，选择持久化（localStorage）；预置供应商的默认名称和说明
  随界面语言切换，管理员自定义的渠道名称始终原样展示。
- **外观**：左右布局、可收缩侧边栏、浅色/暗黑主题、响应式；图表支持 `prefers-reduced-motion`。
- **模块**：概览（Dashboard）、渠道、模型、API Keys、Analytics（用量分析 / 请求日志）、System。
- **网站访问地址**：System 页自动检测当前浏览器 Origin，管理员确认保存后作为部署的规范访问
  地址；只接受不含路径、查询、凭据和锚点的 HTTP(S) Origin。该设置用于首页接入地址、复制命令
  和 Agent Skill 提示词，不代替 Cloudflare 自定义域名或 DNS 配置；未保存时回退到当前访问地址。
- **快速调用**：首页可创建 1 小时有效的临时 Gateway Key，并把已生成的调用命令复制到剪贴板。
  明文只缓存在当前站点的浏览器 `localStorage`，刷新页面后在到期前仍可继续复制；到期时自动
  清除并恢复为未创建状态，不通过管理 API 再次读取明文。

### 3.2 渠道

- **协议与端点**：Chat、Responses、Messages 是固定的三种协议类型，每行展示固定请求 path 与
  可编辑 Base URL。预置渠道按已确认的供应商元数据默认勾选并预填端点，自定义渠道默认启用
  Chat；用户可勾选协议并修改实际 Base URL，模型列表不得用于推测协议能力。
- **重复约束**：相同预置供应商（或相同自定义端点集合）不得重复配置同一 Provider Key；模型
  的同一渠道也不得重复绑定，API 返回 `409 resource_in_use`，控制台展示明确提示。
- **检测与导入**：添加渠道必须先执行"检测连接与模型"，并在提交前展示协议、检测结果和模型
  清单；检测阶段不创建渠道、不写 D1，连接信息或 Key 改动后必须重新检测。检测完成后展示可
  勾选模型清单，默认全选，支持全选/取消全选/逐项选择；"保存"只保存渠道及完整模型库存，
  "保存并导入网关"只导入已勾选模型。检测失败视为已完成一次预检，允许仅保存后手工维护；
  未勾选模型时禁用导入。
- **卡片交互**：渠道页为响应式竖向卡片网格，以现有卡片的精简样式（头部、指标占位、内容骨架
  与底部添加按钮）作为添加入口，不提供渠道搜索；现有卡片展示状态、协议、缓存余额、套餐余量占位、
  模型总数和最多 3 个模型预览（其余以 `+N` 表示）。高频操作"管理"和"测试"直接可见，
  启停、删除等低频操作收纳到更多菜单。保存成功展示轻量完成动效与持续成功状态，不阻塞
  余额查询、模型导入或后续操作。
- **摘要性能**：多渠道摘要使用批量查询，不按卡片产生 N+1 查询；模型发现与余额查询只由
  用户操作触发，不使用 Cron。
- **删除**：删除渠道前展示关联实例与受影响统一模型数量；有其他渠道实例的模型只移除当前
  实例，失去最后实例的模型在确认后软删除（历史 usage 保留）。

### 3.3 模型

- **创建**：从模型网格内与真实模型卡片同构的精简新增卡片打开统一弹窗；支持从渠道库存勾选
  导入，或从 30 个常见模板 / 自由输入创建。
- **结构**：统一模型（unified model）+ 渠道实例（channel instance），可编辑 ID 与稳定直达
  别名；同一模型可绑定多个渠道实例，按实例顺序路由。
- **定价**：每个渠道实例可配置输入 / 输出 / 缓存命中单价（每百万 Token）和 USD / CNY
  币种元数据。

### 3.4 价格库（model_prices）

- 管理员可维护模型基准价（输入 / 输出 / 缓存，USD/CNY），渠道导入时自动预填表单。
- 内置 30 个经官方页面核验的主流模型 USD 按量基线；分层计价模型采用最短上下文首档，完整
  口径、核验日期与来源见[供应商与模型](PROVIDERS.md)。升级只替换仍等于旧内置值的行，不覆盖
  管理员已经修改的价格。
- **优先级**：渠道实例价 > 价格库基准价 > 未定价（不计费）。
- 请求完成时按 Provider 上报 Token 和实例价格计算整数 micros，缓存 Token 使用缓存价；结果
  汇总到用量、密钥每日用量与首页指标。
- **已知限制**：当前聚合表只有 `cost_micros`，没有币种维度，也没有汇率换算。因此不同币种
  混用时汇总值不具备财务意义。修复前部署者应统一使用一种记账币种，界面中的费用只能视为估算。

### 3.5 密钥与限额

- **生命周期**：创建、一次性明文展示、启停和删除。创建时可选择 1 / 7 / 30 / 90 天或永久；
  编辑时可选择精确到本地日期和时间的到期时间，留空表示永不过期。列表显示具体到期时刻和
  “已过期”状态，并允许直接续期。
  后端仍保留重新生成兼容接口，但当前控制台不提供入口。
- **限额**：每分钟 RPM（isolate 内尽力窗口）、每日请求 / Token 预算（D1 权威扣减）、到期
  时间、模型白名单；超额返回 429/403，密钥过期返回 401。

### 3.6 网关协议与路由

- **协议**：OpenAI Chat、OpenAI Responses、Anthropic Messages。
- **转换**：Chat ↔ Messages 的文本、工具调用、usage 和 SSE 公共子集；无法无损表达时直接报错。
- **路由**：原生协议优先、固定优先级、完整别名直达。
- **Fallback**：连接错误、超时、408、429、部分 5xx 和可靠额度不足错误；只在响应开始前回退。
- **熔断**：连续故障后在当前 isolate 冷却，不主动探测 Provider。
- **流式**：SSE 增量解析与透传，客户端取消向上游传播。

### 3.7 用量与 Analytics

- **聚合**：5 分钟聚合桶（始终记录，不受日志开关影响），维度为密钥 / 统一模型 / 最终渠道，
  分别记录总输入、缓存命中与输出 Token，并额外记录流式 TTFT、延迟采样数和回退信息；保留期
  与 usage 一致（30 天）。
- **用量分析页**：今日 / 7 天 / 30 天与日历点选的自定义时间范围、模型和密钥过滤、聚合粒度（5 分钟 /
  小时 / 天）；指标卡（请求量、平均延迟、平均首 Token 延迟、成功率、Token、预估费用）；首
  Token 延迟仅统计能够观察到首个有效输出的流式请求，无流式样本时显示 `—`；
  Request trend 折线图与 Token consumption 三色堆叠柱状图（非缓存输入 / 缓存 / 输出，含真实
  时间轴、数值轴、单位和时间标签）；两张图桌面端 1:1 并排、移动端堆叠；图表
  根据可视宽度将原始桶合并为最多 48 个展示桶，使分钟、小时、天粒度具有一致的线宽与柱宽；
  7 天范围默认按天聚合，前端以零值补齐无请求桶；模型维度明细表。
- **分析导航与筛选**：用量和日志页在标题下展示用途副标题，共用轻量胶囊分段导航；筛选控件
  采用 48px 等高、弱边框和大圆角，桌面端按主要维度排成一行，窄屏自动切换为两列或单列。
- **写入**：完成路径一次 D1 `batch()` 提交聚合、密钥日用量与可选日志，同一 `waitUntil`
  执行，不阻塞模型响应。

### 3.8 请求日志与可观测

- **开关**：总开关 + 异常 / 正常日志独立开关；关闭时完全不写 `request_logs`。
- **维护**：清空全部请求日志属于系统级危险操作，只在 System 的日志设置模块提供；执行前必须
  明确确认，且不删除 Analytics 用量聚合或费用统计。
- **上下文**：默认关闭；开启需二次确认，请求和响应各最多 4 KiB 预览，`MASTER_KEY` 派生密钥
  AES-GCM 加密存储，列表接口绝不返回上下文明文。
- **筛选与分页**：状态、模型、密钥、渠道、精确 Request ID；游标分页，默认不轮询、不
  COUNT，最多 100 条/页；详情抽屉展示路由尝试、回退、Token、费用、延迟、脱敏错误。
- **保留**：日志 1–7 天（控制台可调），每日 Cron 清理。
- **可观测**：脱敏结构化日志、`X-Gateway-Timing`、`Server-Timing`、`/health`、
  `/v1/openapi.json` + `/v1/api-docs`。

### 3.9 安全

- Provider Key 用 `MASTER_KEY` AES-GCM 加密存储；Gateway Key 服务端只存哈希，普通密钥明文
  只显示一次。首页临时密钥由服务端标记并固定为 1 小时，不允许续期或重新生成；过期后列表
  立即隐藏，并在后续创建或删除任意 Gateway Key 时顺带物理清理，不占用 Cron。明文按 3.1 节
  约定只在当前浏览器保留至到期。
- 控制台需要登录；日志不记录任何密钥凭证；默认不存对话内容。

### 3.10 实验性 ChatGPT Codex 订阅渠道

- **目标**：允许个人部署通过 ChatGPT Device OAuth 绑定 Plus / Pro 账户，并将该账户可用的 Codex
  Responses 能力接入现有统一模型路由。它不是 OpenAI 公共 API，也不承诺兼容普通 ChatGPT
  网页会话。
- **范围**：第一阶段只提供单账户、原生 `/v1/responses`、模型发现、订阅额度原始查询、自动
  Token 刷新、重新授权与删除。Chat / Messages 转换、多账户额度路由和团队共享不在本阶段。
- **交互**：Channels 页面提供带“实验性”标识的订阅卡片。用户取得设备码后前往 OpenAI 授权页；
  Dashboard 按服务端建议间隔轮询，授权完成后自动创建 Codex 渠道，随后由用户选择并导入模型。
- **安全**：Access Token、Refresh Token 和临时 Device Auth ID 使用 `MASTER_KEY` + AES-GCM
  分别加密；管理接口只返回脱敏账户信息和状态。Refresh Token 可能轮换，跨 isolate 刷新通过
  D1 版本号与短租约串行化，401 最多强制刷新并重试一次。
- **Free Tier**：授权状态、Token 和刷新租约只使用 D1；不增加 Cron、KV、R2、Queue 或 Durable
  Object。过期设备授权在后续授权操作中惰性清理。
- **稳定性边界**：ChatGPT Codex 后端不是公开 API，端点、请求字段和风控均可能变化。功能默认
  标记实验性；正式合入前必须从真实 Cloudflare Worker 出口完成 Device Flow、模型、额度以及
  流式/非流式 Responses 验证。若 Cloudflare 出口或 TLS 指纹被拒绝，不引入外部中继来规避。

## 4. 已实现：Agent 管理入口

### 4.1 总体目标

在不向 Agent 暴露管理员密码、Provider Key 明文或 `MASTER_KEY` 的前提下，让用户可以授权
Codex 等 AI Agent 通过标准管理 API 完成日常运维。该能力由两层组成：Management Key 提供
可删除的机器身份，官方 Skills 提供可读、可审查和可复用的操作流程。

```text
用户创建 Management Key（选择权限与到期时间）
  → 将网关地址和该 Key 配置给 Agent
  → Agent 安装 MyGateway 官方 Skill
  → Skill 调用版本化 Management API 查询或变更资源
  → 控制台可查看来源、最后使用时间并随时删除授权
```

### 4.2 Management Key

- **身份边界**：新增独立的 Management Key，不复用 Gateway Key、Provider Key 或管理员会话。
  Gateway Key 只能调用模型；Management Key 只能调用明确开放的管理 API，不能调用模型。
- **生命周期**：支持创建、一次性明文展示、名称、永久或精确到期时间、启停、删除、最后
  使用时间和 Key 前缀展示；服务端只保存哈希，密钥明文不可再次读取。
- **权限模型**：MVP 提供易理解的 `read` 与 `write` 两档。`read` 只能查询，`write` 可调用开放
  资源的变更接口；修改日志策略、清空日志、管理管理员凭据和签发 Management Key 本身不开放。
- **API 范围**：为渠道、模型、Gateway Key、用量、请求日志和系统状态提供稳定、版本化、机器可读
  的管理 API；写操作保持现有校验、重复检测和影响分析，不因调用方是 Skill 而绕过约束。
- **安全与审计**：鉴权成功的管理请求记录 Management Key ID、Request ID、路径与结果，永不记录
  请求体或 Key 明文；错误响应不得返回 Provider 凭据或加密字段。认证失败限速随管理登录加固
  在后续安全迭代统一实现。
- **Free Tier 约束**：鉴权与权限解析使用 D1 和短期 isolate 缓存，不引入 KV、Durable Objects 或
  额外常驻服务；列表接口继续使用分页和批量查询。

### 4.3 官方管理 Skills

- **交付形态**：仓库保存可审查、可二次开发的 Skill 源码，每次 Dashboard 构建同时发布到部署
  网站的 `/skill.md` 与 `/skill.json`；用户直接让 Agent 读取自己的网关域名，不依赖代码仓地址
  或额外脚本。Skill
  只要求配置网关管理地址和 Management Key，不要求提供 Cloudflare 主账号凭据。
- **首个 Skill**：`mygateway-admin` 将渠道、模型、Gateway Key、余额、用量与只读诊断收敛为
  一个入口，减少安装和权限配置成本；部署、迁移与 Cloudflare 账号操作不在该 Skill 范围内。
- **交互要求**：读取和诊断可直接执行；删除、清空、凭据轮换等高风险操作必须先展示影响并取得
  用户明确确认。Skill 必须复用 API 的结构化错误，不通过页面 DOM 自动化管理资源。
- **版本与兼容**：每个 Skill 声明支持的 MyGateway API 版本；服务端提供能力发现接口，版本不兼容
  时停止写操作并给出升级建议。控制台提示词只要求 Agent 安装托管 Skill；版本检查由 Skill
  自身负责，每次使用前读取 `/skill.json`，发现新版本后先从 `/skill.md` 更新再执行管理操作。
- **开源扩展**：文档说明如何复制官方 Skill 创建自定义流程；社区 Skill 可独立发布，但不得默认
  获得超出其声明范围的权限。

### 4.4 验收标准

- Management Key 的权限、到期、停用和删除在 HTTP 集成测试中均不可绕过；
- Management API 测试完成“创建渠道 → 创建统一模型与实例 → 创建 Gateway Key”的真实旅程；
- 只读 Key 无法执行写操作，过期、停用或已删除 Key 返回 401，权限不足返回 403；
- 日志和错误响应中不存在 Management Key、Gateway Key 或 Provider Key 明文；
- 官方 Skill 提供自包含 HTTP 操作指引、部署站点的 OpenAPI / capabilities 发现入口、示例配置和
  二次开发入口，不依赖仓库 helper 或 Cloudflare 账号。

## 5. 产品边界（当前明确不做）

- Responses 与 Chat / Messages 之间的协议转换；
- Gemini 原生协议、Embeddings、Images、Audio、Realtime、Batch 和 Files；
- 同渠道自动重试、流输出后的 Fallback；
- 动态价格路由、自动套餐扣减和精确账单；
- 面向普通 Provider 的通用 OAuth、多用户、RBAC、Team/Project；
- Prompt/Response 存储或语义缓存；
- 跨 isolate 强一致的熔断、限流或预算状态（RPM 为 per-isolate 尽力窗口，每日预算以 D1 为准）。

## 6. Roadmap

### P0：稳定版前必须完成

- 为 Analytics、请求日志和密钥日用量补齐币种维度，或明确收敛为单一记账币种；迁移后 UI
  必须分币种展示，禁止把 CNY 与 USD 相加后标成美元；
- 增加管理登录失败的有界限速，并补充认证 API 安全测试；
- 使用 OpenAI SDK 验证 Chat 与原生 Responses 的真实流式 / 非流式调用；
- 使用 Anthropic SDK 验证原生 Messages 与 Messages → Chat 转换；
- 建立 Free Tier 生产指标基线（CPU、D1 rows read/write、缓存命中率）。

### P1：近期体验

- 根据社区反馈扩展 Management API 的分页、批量操作和 OpenAPI Schema；
- 评估是否拆分垂直 Skills；部署升级 Skill 在稳定版发布流程确定后再设计；
- 完善自定义渠道协议端点编辑校验和变更影响提示；
- 完善 Anthropic 错误 envelope 和图片内容公共子集；
- 密钥页面展示每日用量与剩余预算。

### P2：后续候选

- Provider Adapter 能力矩阵与更多官方余额接口；
- Responses ↔ Chat 转换；
- 缓存命中的预算扣减策略；
- 多用户和 RBAC；
- 只有需要共享强状态时再评估 Durable Objects。

Roadmap 不是已承诺的发布日期；已发布变化以 [CHANGELOG](CHANGELOG.md) 为准。
